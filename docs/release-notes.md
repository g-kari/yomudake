# 更新記録

## 2026-10-10: Workersの公開DNS照会をnative fetchに対応

- 本人の再試行で `SOURCE_DNS_ERROR` が返り、取得元・AIより前のDNS確認で止まることを確認。固定版workerdで同じコードを実行すると、DoHの `redirect: 'error'` がRequest作成時にTypeErrorとなり、外向き通信より前に失敗することを再現した。
- DoHは `redirect: 'manual'` に変更し、既存のHTTP成功判定で全転送応答を拒否する。固定Cloudflare resolver、A/AAAA両方、CNAME関連性、全回答IP、サイズ・総時間・各転送先の再検査、strictly-public設定を維持する。resolverの切替・DNS確認の省略は行わない。
- 安全な公開DNS照会で確認した、Questionの末尾dotがない応答にも対応。正確なhostname/query typeの一致は維持し、末尾dotを0個か1個だけ同一視する。
- Wranglerで既にlockされていたMiniflareを同じ固定版でテスト用の直接依存に宣言。native workerdの合成ネットワーク試験を追加し、通常・dotなし応答、DoH転送拒否、混在した非公開IP拒否、取得元転送時のDNS再照会を検証する。本番binding/設定・依存のバージョン・リソース・認証を変更しない。
- この修正は再現したDNS段階のコード不具合を対象とする。実X投稿の取得・変換成功は未確認で、X専用adapterやアクセス制限の回避は含まない。

## 記事一覧の読み込みと復旧

- 記事一覧の読み込み中と、取得に失敗した状態を一覧の近くに表示します。未取得や失敗を「保存した記事がない」状態として表示しません。
- 「記事一覧を再読み込み」で、画面を開き直さずに再試行できます。連続操作による二重取得を抑え、再失敗しても操作を残します。
- 再取得はタイトル・本文・元URL・公開確認・表示タブと未保存の警告を保持します。保存自体が成功した場合は、一覧取得の失敗と区別して表示します。
- 不正な一覧応答をエラーとして扱い、最後に取得できた一覧を保持します。新しい一覧取得や保存後の更新より古い応答と、画面を閉じた後の応答は反映しません。
- キーボードで再試行した後は一覧へフォーカスを戻します。待機中に別の場所へ移動した人からフォーカスを奪いません。

合成APIを使った実React画面の回帰テストと、固定版Chromiumのモバイル・デスクトップ検証を行います。本番アカウント・Access・AI・D1書き込みはこの検証の対象ではありません。

## 保存操作時の下書き保護

- 下書き保存と公開は、記事一覧の更新が終わるまで1件ずつ処理します。連続クリックで別の記事IDを作ったり、公開・非公開を同時に送信したりしません。
- 保存中に新しい入力が届いた場合、送信済みの内容と編集中の変更を区別します。新しいタイトル・本文・出典と未保存の警告を保持し、再保存が必要だと表示します。
- 保存失敗や確認できない応答では入力を保持します。再試行は同じ記事IDを使用します。保存に成功して記事一覧だけを取得できなかった場合は、その違いを表示します。
- 古い一覧の応答は保存後の一覧を置き換えません。画面を閉じた後の応答は、再度開いた編集画面へ反映しません。送信済みの保存処理をサーバー側で取り消す保証はありません。

実際のReact編集画面をHappy DOMと合成APIで操作する保存の回帰テストを追加しました。実ブラウザーの描画、本番Access・AI・D1、複数タブや別端末からの同時保存は、この検証の対象ではありません。

## URL変換時の下書き保護

- 保存していないタイトル・本文がある場合は、URL変換で置き換える前に確認します。キャンセルした場合は変換リクエストを送らず、編集中の内容を保持します。
- 新規の空の下書きでは、URLだけを入力してそのまま変換できます。
- 変換に失敗した場合やMarkdown・タイトル・出典URLの形式が不正な応答が返った場合は、現在のタイトル・本文・出典を保持します。空白だけの手編集も、置き換える前に確認します。
- 変換中に新しい入力が発生した場合や画面を閉じた場合は、ブラウザー側のリクエストを中止し、古い応答を画面へ反映しません。Cloudflare側の処理停止を保証するものではありません。
- 連続クリックで同じ変換を二重に開始しません。公開確認チェックは、変換結果を反映したときに解除します。

`npm run check` に、実際のReact編集画面をDOMシミュレーションで操作する合成APIの回帰テストを追加しました。Happy DOMはテスト用の依存関係で、Workerと公開記事の配布物には含めません。ブラウザーによる本番Accessログイン・実AI変換・本番デプロイの検証は含みません。


## HTML書き出しの中継変換抑止

HTMLのダウンロード応答だけに `Cache-Control: no-store, no-transform` を指定し、CDNによる本文への計測スクリプト追加を抑止します。本文、Markdown書き出し、公開閲覧、管理画面、認証、既存CSPは変更しません。合成データでヘッダーと既存経路の回帰を検証し、配備後に実際のHTMLダウンロードの応答バイトを再確認します。保存したHTMLを実行する試験や、Cloudflare全体の計測・セキュリティ設定の変更は含みません。

選択した D 案に合わせ、記事一覧を淡い黄色のインデックス、本文を白いノートページとして整理しました。青みのある文字と控えめな青緑の操作ボタンを使用し、管理画面・公開記事の日本語本文を読みやすいサイズと行間にしています。

- 最初の表示と保存した記事を開くときはプレビューを選択します。Markdown とプレビューは同時表示せず、切り替えても入力・未保存状態を保持します。新しい下書きは Markdown の編集から始めます。
- 記事の選択状態、下書き／公開中、保存した記事の出典と作成日を表示します。安全でない元URLはリンクにしません。
- 公開確認チェック、下書き保存、非公開で保存、公開・更新、共有URL、サインアウトを維持します。モバイルでも公開ページとサインアウトへの移動を表示します。
- 未保存内容の破棄確認、変換・保存の二重送信や古い応答の保護、API・認証・配備設定・マイグレーション・HTML書き出しの no-transform は変更しません。

型チェック、ビルド、実 React 編集画面の合成 API 回帰テストで確認します。本番の本人認証・実 AI 変換・D1 書き込みはこの UI 検証の対象ではありません。

## 出典リンクと外部サイトの確認

- 既存の出典表示を「出典・元の記事」に揃え、Markdown書き出しにも元ページへのリンクを追加しました。元URLのない手書き記事には出典を作らず、保存済みの本文は変更しません。
- 公開本文とHTML書き出しの外部リンクは、サイト名とURL、内容・安全性の注意、戻る／進むを示す確認画面へ移動します。内部リンクはそのまま開きます。移動先URLはリクエストのqueryに入れず、公開記事から確認します。外部ページの取得や自動転送は行いません。
- 確認リンクは本文・出典・更新日時のハッシュに結び付けます。更新・非公開化の後に古いHTMLから開いた場合は、新しい移動先へ差し替えず、記事を開き直す案内を表示します。HTMLの確認リンクにはオンラインの公開記事が必要です。任意のMarkdownビューアーには確認画面を強制できないため、Markdownには注意書きを付けます。
- 管理画面はネイティブdialogで確認し、戻る／Escapeで下書きとフォーカスを保ちます。元の管理画面のiframe禁止は維持するため、管理画面の確認には画像を埋め込みません。
- 公開確認画面だけに、指定されたPixiv作品「やばいこれ毒かも！」（ジセイノク、150221597）の公式埋め込みを表示します。作品を転載・再配信せず、固定の公式iframeだけを許可します。sandboxはスクリプト・フォーム・ポップアップ・上位画面への移動を許可せず、Refererを送りません。PixivにはIPや既存Cookieが届く場合があります。外部サービスが表示できなくても、作品・作者へのリンクと確認操作を残します。
- 確認できた関連作品は現在1件です。選択処理は複数件に対応しますが、実際の表示に複数の画像のランダム性はありません。実作品の画面表示は未確認です。ブラウザー検証では合成の埋め込み応答と表示失敗を使用し、Pixivや外部記事へアクセスしません。

Access・所有者認証・管理API・D1スキーマ・AI取得設定は変更しません。記事とHTML書き出しはスクリプトなし、HTMLダウンロードの no-store / no-transform を維持します。iframeのCSP許可は、公開の確認応答の固定Pixiv embedパスに限定します。
